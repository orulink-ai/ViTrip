# 真实旅行照片：采集、来源核对与超时前保存

## 问题与实测依据

用户希望酒店和景点配上来自官网、旅行平台及小红书原帖的真实照片，并在行程与地图中复用。目前已内置 itinerary-organizer Skill，但尚未接通图片采集、模型图片输入和相册展示。

2026-09-27 使用真实 deepseek-v4.1-flash、Pi 和 Electron，以 Hotel Clover Patong Phuket 与 Wat Chalong 为公开地点样本执行两轮测试：两轮均读取 Skill 和照片说明；部分页面可访问，酒店官网多次出现连接错误，小红书要求登录；Agent 持续尝试导致 180 秒超时，没有 journal 写入。第二轮增加失败处理规则后仍失败。不能把 Skill 加载成功、文字页面读取或自动化回归通过称作照片功能通过。

复现入口：`npm run build` 后执行 `node scripts/live-photo-check.mjs --run`。该测试使用已有模型配置并产生正常调用费用，数据隔离；不在 issue 上传凭据、私人会话或原始本地日志。

## 范围

- 从实际访问的来源页面提取图片候选及上下文，禁止模型编造图片 URL。
- 保存地点身份、原页面、实际图片地址或资源 ID、发布者、说明、采集时间和对应关系证据；发布时间和拍摄时间分别处理。
- 酒店核对分店、地址与房型；景点核对具体地点。区分官方展示、游客发布、效果图及待核对候选，不承诺凭视觉相似度证明真实。
- 接通图片输入前核对模型和供应商接口能力；URL、alt 文字不代表模型看过图片。
- 在运行时处理单次访问耗时、连续失败和整轮预算，为阶段保存预留时间；已取得的资料及时保存。无法取图时保存待采集项，不冒充照片已获取。
- 遇到登录或验证码时说明需要用户接管，可先继续其他来源；不得绕过限制或把搜索缩略图冒充已核对原帖。
- 本地图片缓存与资料持久化；控制资源大小、验证图片类型，避免向远程页面暴露主进程 API 或模型密钥。
- 行程与地图共用照片记录，支持缩略图、大图、来源入口与失败回退。

## 验收

- [ ] 至少一个真实酒店和一个景点取得可追溯图片，并人工核对与来源页面的对应关系。
- [ ] 用明确不匹配的分店或房型样本验证不会被标为已核对。
- [ ] 登录受限、连续网络失败与超时场景会保留阶段成果或待采集记录。
- [ ] 模型确实接收图片内容后才可以声称进行视觉检查。
- [ ] 重启与同一旅行的新会话可读回照片及来源。
- [ ] 真实 Electron 展示照片，行程与地图联动；无图或缓存失败时仍可阅读。
- [ ] 分开报告模型实测、来源人工核对、图片展示和自动化测试结果，明确剩余限制。

## 实现边界

不使用生成图片或无关图库冒充实拍；保留水印与来源标注。先做少量可核对照片的完整流程，不以批量抓取数量作为成功指标。与行程工作区及个性化地图 issue 联动验收。
