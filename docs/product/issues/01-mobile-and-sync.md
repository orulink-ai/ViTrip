# feat: 手机 APP 与旅行资料跨端同步基础

状态：本地草稿，尚未创建 GitHub Issue。
记录日期：2026-09-27。
建议阶段：P0，待讨论。

## 目标

让手机成为旅行中的随身入口，与桌面端使用同一份旅行、行程、待办和记录。

## 范围

- 确定首发平台、客户端技术路线、账号与同步服务方案，并记录取舍。
- 提供旅行列表、行程和待办查看，建立版本化同步契约，为照片和感想预留关联模型。
- 实现离线读取与编辑队列、幂等同步、冲突处理、删除传播及同步状态提示。
- 区分私密原始资料与未来公开内容；不将桌面模型密钥随业务数据同步。

## 验收场景

- 手机修改一条待办后，桌面端可见相同状态；设备重启后仍保留。
- 断网编辑、恢复网络和重复重试不会丢失数据或产生重复记录。
- 两端同时修改或一端删除、另一端编辑时，有明确可恢复的处理结果。
- 不同账号之间资料隔离，退出登录后的本机资料处理有明确规则。

## 依赖与边界

为提醒、旅行记录和生成内容提供基础；当前桌面工程无云同步，不能将其视为已有能力。

核心行为先写失败测试再实现，验证用户可观察结果；遵循项目分层与默认组件规范。涉及浏览器能力时使用真实 Electron 页面验证。提交前运行项目要求的测试与构建。本文只记录需求，不代表能力已实现。
