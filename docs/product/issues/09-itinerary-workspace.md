# 行程工作区：参考 Mindtrip 的按天列表与地点详情

GitHub 跟踪：[Issue #1](https://github.com/orulink-ai/ViTrip/issues/1)。关联：[个性化地图 #2](https://github.com/orulink-ai/ViTrip/issues/2)、[真实照片 #3](https://github.com/orulink-ai/ViTrip/issues/3)。

## 问题与目标

当前行程以总览表和单日详情切换为主，缺少可连续浏览的图文行程。用户希望参考 Mindtrip：在右侧快速看懂每天去哪、何时活动、住哪里，并围绕地点继续查看资料、调整安排和定位地图。

参考：[Mindtrip](https://mindtrip.ai/)。参考用户提供的 Seoul Eats 截图中的按天分组、紧凑照片条目、住宿提示和地点操作入口；不将截图中无法确认的交互当作现有功能。

## 范围

- 默认呈现按天分组、可折叠的连续行程列表；保留每日总览表作为辅助视图。
- 顶部展示已有的行程名称、日期及人数等信息；未知信息不补造。
- 地点条目采用小缩略图、名称、时间、简短说明；缺图时用默认类别图标。
- 点击条目展开照片、来源、详细安排、备选关系及待确认事项，并联动地图。
- 连续入住同一酒店时使用紧凑的住宿提示；明确区分原攻略安排、待确认与已预订。
- 支持在指定日期添加地点、调整顺序；保留稳定地点身份、来源和用户决定。
- 地点间的距离与耗时仅在接入可靠路线数据后展示，标注交通方式和估算依据。

## 验收

- [ ] 多天内容可连续浏览，也可快速定位某一天；窄窗口不会隐藏日期或关键操作。
- [ ] 条目与地图双向定位，切换视图后保留选中的日期和地点。
- [ ] 照片加载失败不影响行程阅读；图片来源可打开。
- [ ] 备选活动不会被排成依次执行的必走路线，住宿不重复展示成多次入住。
- [ ] 调整行程后持久化，重启恢复；旧行程和无图片数据仍可使用。
- [ ] 用真实 Electron 验证阅读、展开、定位、编辑与恢复，并提供截图。

## 实现边界

沿用 React、AI Elements / shadcn 官方默认组件和中性色；增加必要布局与交互，不复制品牌皮肤。Skill 维护整理规则，React 负责呈现。日历和预订交易不是本期必做内容，不能以展示按钮冒充已实现能力。

依赖：真实照片采集与来源记录、个性化地图联动。
