# 旅行 Agent 第一版

目标是把用户的旅行想法持续落实为旅程地图与 Prepare 准备待办。Soul、目标、记忆、推进规则、行动边界和完成标准由 `src/main/travel-agent-charter.ts` 统一定义，通过共享系统指令供 Pi 与 Codex 使用。

## 本版行为

- 初次交流逐步收集目的地、出发地、日期/时长、人数、预算与偏好；有答案不重复询问，缺少关键条件每次问 1—2 项。没有目的地时允许先探索。
- 使用 journal 保存信息和决定，用 plan 保存完整旅程地图，明确区分建议、用户决定与实际预订。
- 两个引擎均提供 prepare 工具，直接维护笔记本中已有的同一份待办。每轮输入包含最新准备状态与当前时间；没有单独的 AI 待办。
- 先读取待办，再携带版本合并新增或修改的事项。保持稳定 ID、保留其他事项与完成状态；如果用户期间修改了清单，拒绝旧版本写入并要求重新读取。
- 完成操作必须附用户明确确认或实际成功结果的依据。该参数属于模型提供的依据，不能替代对真实性的核实；规则要求不得把推荐或打开网页当作完成。
- AI 更新立即同步到现有待办界面，跨会话共享，重启保留。私人笔记正文不因 Prepare 接入而发送给模型。
- 根据未落实事项主动比较酒店、交通等；对话尾声和临近出发的对话中，提示关键未完成事项。

## 当前边界

本版优先验证 Agent 核心，没有新增基础资料表单、独立 Prepare 页面或应用打开时的自动提醒。基础信息沿用 journal；自然语言口述仍由现有模型处理。没有接入新的语音输入能力。用户首次填写表单与后续对话应共享这些资料，下一版再实现具体界面与结构化字段。

出发日期尚无独立结构化字段，不能可靠实现打开应用的日期提醒；本版禁止 Agent 声称已经设置提醒。酒店交易继续使用现有具体操作确认规则。

## 验证方式

单元测试先验证失败，再实现：共享待办持久化、已完成项保护、其他旅行隔离、旧版本冲突、重复事项合并、完成依据约束。

真实 Electron 测试通过受控模型接口发出 prepare 调用，验证实际工具执行、界面实时更新、下一轮最新状态与重启恢复。此类测试验证运行链路，不代表真实模型在所有旅行对话中都能稳定遵循工作章程。

建议人工试聊：

1. “两个人想去日本七天，喜欢轻松一点，还没定日期。”观察是否先补关键条件。
2. 明确日期和预算，要求大致路线；观察是否保存旅程地图并产生少量可执行待办。
3. “酒店只是选好了，还没有预订。”观察是否保持未完成。
4. 手动勾选一项，再继续对话；观察是否读取最新状态并避免重复提醒。
5. 修改路线或日期；观察是否重新检查受影响的住宿与交通。
