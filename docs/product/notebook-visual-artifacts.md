# 图文笔记与回复中的笔记入口

用户的默认阅读偏好：真实相关图片配简短要点。笔记先给结论，每个地点或餐厅用照片加少量关键信息；长来源和核实记录折叠保留，重要风险仍放正文。聊天只讲结果与下一步。

## 交互

保存或更新笔记成功后，回复下方使用 assistant-ui Elements 的 File 组件显示文件名及右侧打开按钮。点击会展开右侧笔记本，并选中该文档的最新版本。用户无需再从目录手动寻找。

入口来自持久化的工具成功回执，而不是从聊天文字猜文件名：失败、进行中和只读操作不生成入口；一次回复中同名笔记多次保存只显示一项。历史成功回执也适用。文档切换等待用户正在进行的保存，保留失败草稿。离开笔记标签后不会用旧跳转请求覆盖用户后来选择的文档。

## 配图

Agent 的共享系统指令新增图文偏好。优先复用本旅行的匹配照片，或通过现有 photo_candidates → save_photo 获取真实页面照片。插图写作 `![说明](vitrip-photo:64位照片id)`。

笔记页面使用官方 Image 组件显示已缓存图片、放大预览和来源链接。图片只从本旅行缓存读取，不放开页面加载任意外部图片；跨旅行、无效或已丢失的图片显示简短的不可用提示。无法取得可靠照片时，Agent 应明确说明缺图，不能使用无关图片或生成图片冒充实拍。

## 远程配图落盘修复（2026-09-28）

根因：Markdown 写入远程图片 URL 时没有调用照片保存工具，预览却仅允许读取本旅行的已缓存照片。因此正文保存成功并不代表图片已保存。

新增 NotebookMedia 主进程服务，在 Agent 写入、用户保存和打开旧文档时解析 Markdown 图片节点（含引用式图片，不修改普通链接及代码）。HTTP(S) 图片经限时、限大小下载和真实解码后，写入该旅行 `notebook/assets/<内容哈希>.png`，Markdown 改成相对引用。已有 `vitrip-photo:` 缓存引用保持兼容。图片读取 IPC 仅接受本旅行 assets 下的严格哈希路径，拒绝任意路径和符号链接，不开放网页图片 CSP。

旧文档补齐使用版本检查；下载期间若有用户编辑，不覆盖新内容。无法下载时保留原地址与正文，工具返回 imageWarnings，UI 显示“正文已保存，配图未完成”，可重试。预览读取本地字节，成功保存的图片不依赖原站持续在线。当前自动导入覆盖 Markdown 内联与引用式图片，HTML img 不在本次范围内。

验证覆盖字节落盘、引用替换、断网重启、旧文档迁移、HTTP 错误、非图片响应、版本冲突、跨旅行隔离和已有图文笔记入口。

修复后隔离验证：完整构建通过；115 项单元测试通过，1 项真实 Codex 测试未启用而跳过；9 项相关 Electron 用例通过。另用用户实际问题笔记的副本进行联网验收，两张原始来源图片均成功保存为本地 PNG 并在预览中显示（共10项 Electron 验证）。原始用户笔记未被测试修改，新版打开时按上述流程自动补齐。没有重跑全桌面用例集。
