# ViTrip

独立旅行规划桌面客户端：中间对话，右侧真实本地浏览器与可视化行程。

产品未来方向、分阶段议题与创始人原话见本文末尾的[产品愿景与路线图](#产品愿景与路线图讨论稿)。规划中的能力不代表当前已实现。

**AI Elements / assistant-ui + Pi / Codex + Jev + Electron + React + TypeScript + SQLite**。不以 LibreChat 为运行依赖。AI Elements 由官方 CLI 安装，其依赖的基础 UI 组件一并保留。

## 打开与使用

双击项目里的 **ViTrip.app** 或 **启动 ViTrip.command**。

- 在左下角「模型设置」配置主模型与 Jev 密钥。密钥经操作系统加密保存在本机，不包含在源码或安装包中。
- 主模型默认：`deepseek-v4.1-flash`；百炼接口：`https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。
- 浏览器决策模型：`typesafe/jev-1.13`；OpenRouter 接口：`https://openrouter.ai/api/v1/systemone`。它是结构化决策接口，不是 Chat Completions。
- 告诉助手目的地、出发时间和偏好。它可以查询网页，操作浏览器并更新右侧行程。
- 右侧可手动输入网址；点击「接管」暂停 AI，手动处理后「交还 AI」。模型会重新观察页面。
- 「行程」展示每日安排与来源，可导出独立 HTML。
- 对话中的「执行过程」复用 AI Elements Chain of Thought 和 Tool 组件，显示工具步骤、耗时、结果与错误；可折叠展开，记录随会话保存并在重启后恢复。中断的步骤明确标记，不生成虚构的思考内容。
- 选中 AI 回复文字后可「添加到对话」或「标记到笔记本」；引用会随问题发送，点击引用可回到来源。
- 「笔记本」按旅行文件夹共享多篇独立 Markdown 文档，可选择、新建、编辑、预览和另存为。Agent 使用 notebook 工具整理攻略、预算、对比和清单，先读后更新同主题文档。旧的随手笔记、引用、待办与画板保留；取消标记不删除已插入的笔记。
- 个人笔记和画板独立保存，不由 AI 自动改写，也不自动发送到模型。当前画板为单人本地使用，不含多人协作；HTML 行程导出暂不包含笔记和画板。
- 「查看示例行程」明确标注为静态示例，不代表实时查询。

## 对话阅读与消息操作

- 生成中仍可输入、引用和上传附件；按 Enter 或点击「打断并发送」，先取消当前执行，再沿用会话上下文处理补充要求。Shift+Enter 换行。「停止生成」只停止任务，保留已输出内容和正在编辑的草稿。此模式是中断后继续，尚未接入引擎原生的不中断 steer / 排队跟进。

- 长对话使用官方 [Conversation map](https://www.assistant-ui.com/elements/conversation-map)：按轮显示刻度、悬停预览、点击定位；对话栏窄于 420 px 时卸载导航与预览，给正文让出空间。
- 生成时使用官方 [Thinking indicator](https://www.assistant-ui.com/elements/thinking-indicator) 显示当前工作和本轮耗时；回看历史不打断生成，官方滚动按钮可回到最新内容。
- Thread 自带 Message pair / Message actions 布局，复制有勾选反馈，赞/踩仅保存在本机；文字草稿按会话保存，切换和重启后恢复。
- 重新生成保留原回答，通过官方分支按钮切换；回答版本和选中路径随会话保存。Pi / Codex 使用所选路径建立独立模型上下文。版本切换只切换对话，不回滚共享行程或已执行的外部操作。

## 上传附件

输入框左下角「+」使用 assistant-ui Elements 官方 Attachment 组件，可选择多个文件，也支持拖入附件和粘贴图片。发送前可移除附件，允许仅发送附件；已发送的附件和图片缩略图随对话持久保存。每条消息最多 8 个文件，单个文件最大 20 MB。

UTF-8 文本附件会提供正文（长文本截取前 32,000 字符，原文件仍可继续读取）；图片提供实际像素，Pi 需启用图片输入，Codex 直接接收图片。PDF、Office 等文件保留原件并向 Agent 提供本机路径，由文件工具、CLI 或相应 Skill 读取，不内置通用文档转换器。

## 切换 Pi / Codex

输入框下方的 Agent 选择器使用 assistant-ui Elements 官方 [Model selector](https://www.assistant-ui.com/elements/model-selector)，可以直接切换 Pi 与 Codex；草稿不丢失，运行中禁止切换。设置作用于后续请求，Pi 的接口、模型和密钥独立保留。

Codex 使用本机 `codex app-server`，无需 Docker 或 HarnessRouter。先安装 Codex CLI 并运行 `codex login`；macOS 也会检测 `/Applications` 和 `~/Applications` 下 Codex / ChatGPT 桌面应用的内置可执行文件，并优先使用版本较新的可用程序。ViTrip 不复制或读取 Codex 登录令牌，登录与密钥存储由 Codex 管理。

在「模型设置」选择 Codex 后，从本机 Codex 动态读取可用模型及各自支持的思考强度；输入框旁的模型按钮也可打开设置。选择随设置保存，后续请求（包括恢复已有会话）传入模型与强度。未指定模型时沿用本机 Codex 配置。此设置独立于 Pi 模型，未安装、未登录、模型不兼容或进程异常都会显示实际错误。

左侧会话标题支持双击重命名。点击当前会话或跳转当前会话的消息不会停止正在执行的请求，重新加载界面也会恢复运行状态。最后一条用户消息尚无回复时，可点击「继续回复」，保留原消息重新执行。

两种引擎使用相同的旅行数据与本地浏览器工具。Codex 支持流式回复、工具执行记录、图片结果、命令/文件审批、停止、接管和会话恢复。每个对话的 `codex-thread.json` 仅记录 Codex thread ID；Pi 原生会话文件独立保留。切换引擎时传入应用对话记录与共享旅行资料，不迁移原生工具历史。后台手册整理使用独立临时 Codex 会话，仅开放旅行工具中的 journal / plan / notebook。

接入依赖 Codex 的实验性 dynamic tools 协议。已实测 `codex-cli 0.155.0-alpha.9.2` 的真实工具调用和跨进程会话恢复；旧版本若提示模型要求更新 CLI，请升级或选择该版本支持的模型。原生命令遵循 workspace-write 沙箱和逐次请求审批策略，未知交互请求不会自动批准。

开发验证：`npm test`、`npm run build`、`npm run test:e2e`。端到端测试使用协议替身驱动真实 Electron 浏览器；`VITRIP_LIVE_CODEX=1 npx vitest run tests/codex-live.test.ts` 会使用本机已登录账号执行真实模型请求，验证 journal 调用与会话恢复。

## 架构与能力

- **Pi 0.87.1** 管理流式对话、工具调用、压缩与持久会话。每个旅行独立保存完整工具记录。普通对话开放 Pi 内置 read、bash、edit、write、grep、find、ls、powershell 工具，并保留旅行工具；powershell 需要本机已安装对应运行时。后台自动整理仅开放 journal、plan 与 notebook。
- **AgentRuntime** 将旅行执行接口与 Pi / Codex 适配器分离；Pi 默认使用 DeepSeek，Codex 使用自身模型配置。
- **Jev** 从当前 DOM 快照选择操作和元素；执行前校验候选、概率和页面是否变化。一次最多12步，连续三次无进展停止。DONE 仍需要核实页面证据。
- **Electron WebContentsView** 显示真正的本机 Chromium 网页，CDP 执行鼠标点击、键盘输入。不是网页 iframe，也不依赖云端浏览器。
- 表单提交、Enter 和识别出的预订/支付等敏感点击需要逐次确认。密码和支付等敏感字段不进入快照，不允许 AI 填写。
- 接管先取消模型请求，再等待当前浏览器操作结束；恢复时读取最新页面，废弃旧引用。
- SQLite 保存对话与行程，Pi 保存工具历史。密钥通过 Electron safeStorage 加密；renderer 只收到已保存标记。
- 远程网页禁用 Node、启用 sandbox/contextIsolation，没有应用 preload API。交互行程由可信 React 组件呈现；旧手册预览与 HTML 导出转义内容并禁止脚本。

## 当前边界

这是可运行的早期版本，尚未完成真实酒店或机票站点的完整预订验收。

- 使用 ViTrip 自己的本地浏览器 Profile，需要在其中登录；不会读取系统 Chrome 的现有 Profile。
- 浏览器控制基于主文档 DOM 与 CDP，不是视觉驱动的全电脑操控。复杂 iframe、Canvas、验证码和部分登录弹窗需要接管。
- 当前共享一个浏览器页面；新窗口在当前页打开。暂不支持下载、硬件权限、原生 SELECT 操作；当前网址不随重启恢复。
- 敏感操作识别基于表单语义与文字规则，不能覆盖任意网站的所有交易入口。最终预订与付款宜人工完成。
- 网页正文、普通表单值和聊天内容会发送到对应模型服务。
- 无云端同步、多账号、路线导航 API、自动更新或应用商店发行。macOS 包使用本机 ad-hoc 签名，未公证。

## 开发

Node.js >= 22.19；当前验证平台为 macOS Apple Silicon。

```bash
npm ci
npm start
npm test
npm run build
npm run test:e2e
npm run package
npm run test:package
```

界面统一使用 AI Elements / shadcn 默认组件样式和中性色，不额外设计主题或装饰卡片。

AI Elements 是 React 源码组件，这里用 Vite 构建 renderer，无需运行 Next.js 服务。Pi 与 Jev 在 Electron 主进程运行，通过受校验的 IPC 推送 UI 事件。

- `src/main/agent.ts`：Pi 运行时、显式旅行工具、流式事件与持久会话。
- `src/main/activity.ts`：工具执行事件适配、结果截断、密钥脱敏与中断标记。
- `src/main/jev.ts`：决策协议、候选校验、浏览器循环及文字生成。
- `src/main/browser.ts`：真实浏览器、页面快照、元素引用与 CDP。
- `src/main/control.ts`：串行操作和接管。
- `src/main/storage.ts`：SQLite 与系统加密。
- `src/main/index.ts`：窗口、IPC、会话编排、确认与导出。
- `src/renderer/`：旅行工作区与官方 AI Elements 组件。
- `tests/`：核心测试及真实 Electron 端到端测试。

运行数据：`~/Library/Application Support/ViTrip/`；数据库 `vitrip.sqlite`；Pi 会话 `sessions/<trip-id>/`。删除该目录会清除聊天、模型设置和登录状态，请先备份。

## 旅行文件夹与交互行程

「新的旅行」创建文件夹，每个文件夹可展开多个会话。旅行名称旁的“…”菜单可改旅行名或新建会话；会话的“…”菜单支持改名、移动及删除。手动设置的名称不会被首条消息覆盖。

右侧「行程」有三个视图：

- **页面**：React 渲染按天排列的活动与页内地图。点击活动的「在地图中查看」定位地点，地图的「查看行程条目」返回正文。AI 通过 `plan` 更新结构化数据，不生成可执行页面代码。
- **地图**：展开地图、按日期筛选、选择地点。与页面共享地点和选择状态；虚线仅表示相邻活动的顺序，不是道路导航。没有可靠坐标的活动保留为「待定位」。
- **已整理**：可以搜索偏好、已确认决定、问题答案、提醒和待核实事项。条目按稳定 ID 合并，修正同一个问题不删除其他事项，导出 HTML 时一并包含。

同一旅行的所有会话共享页面和已整理资料；每轮对话注入最新资料，必要时追加自动整理。不同旅行隔离。旧版数据首次启动会自动迁移，每个旧行程成为一个文件夹，原聊天与计划保留；之后可把会话移到同一文件夹。移动会话不会搬走或删除原旅行的共享手册。

真实百炼模型已验证两个独立会话连续编辑同一份手册：第一轮记录卡塔海滩、预算和偏好；第二轮沿用已有资料补充出海提醒，原条目保留。自动整理仍可能遗漏或误解，应检查已确认与待核实标记。


### 地图与旧版手册

地图使用 MapLibre GL JS（本地打包 Worker）和 OpenStreetMap 标准瓦片。只有当前视图请求底图，采用 Chromium HTTP 缓存与 ViTrip User-Agent；没有离线底图下载。底图失败时保留地点、顺序和正文，可点击重试。OSM 公共瓦片是尽力服务，规模化分发前需评估合适的瓦片服务商：[使用政策](https://operations.osmfoundation.org/policies/tiles/)。

活动可选 `location` 字段包含 WGS84 经纬度、地点名、`precision`（`place` / `approximate`）和可选坐标来源。它随 Plan 保存在 SQLite，跨会话共享。示例京都行程坐标标为大致位置，没有实时检索或导航含义。

已有 HTML 不删除：没有结构化行程时保留隔离预览和「整理成交互行程」入口；已有 Plan 时，旧内容可通过页尾「旧版手册」展开。导出仍为无脚本 HTML，包含当前计划、历史手册、离线地点摘要、在线位置链接及共享知识。交互地图本身不打包进导出文件。

地图验收包含真实 Electron / WebGL / MapLibre Worker、日期筛选、正文与地图双向定位、IPC 更新保留选择、失败后重试和重启恢复。自动测试只替代外部瓦片网络边界，不模拟地图引擎。


## 聊天组件与界面语言

聊天主体使用 assistant-ui 官方 Thread、Composer 和 Quote 组件，通过 ExternalStoreRuntime 连接 Electron IPC；SQLite、Agent 和浏览器控制仍由主进程管理。组件源码保留在 src/renderer/components/assistant-ui/elements，只增加中文文案与旅行功能插槽，保留原始样式。引用的来源、标记笔记、工具执行过程与审批流程继续使用现有业务数据。

侧栏底部支持简体中文 / English 即时切换，偏好保存在本地并在重启后恢复。切换只影响界面文案，不翻译已有聊天、旅行名称、笔记及生成的行程内容。消息编辑、重试生成、语音和附件等尚未接入的能力不作为可用功能开放。

assistant-ui 的 MIT 许可证保留于 docs/ASSISTANT-UI-LICENSE。依赖版本由 package-lock.json 锁定。

## 本机工具与飞书 CLI

普通对话可以用 Pi 官方内置工具执行命令、读写文件、查找文件及搜索内容；调用和结果会显示在执行过程中，停止生成会取消正在执行的命令。默认工作目录为当前会话目录，可按任务使用其他路径。这些工具使用当前系统用户权限，工作目录不构成文件系统沙箱；远程网页仍不能访问应用 preload API。

飞书能力复用本机安装的 `lark-cli` 和现有认证，不复制凭据到项目或安装包。应用会补充桌面启动时的 PATH，支持常见 Homebrew、nvm、Volta 和本地 bin 安装路径，并读取登录 shell 的 PATH。飞书 CLI 未安装时会明确告知模型，不影响其他工具。

启动每轮会话时，按以下顺序发现 `lark-*` 技能（同名优先使用前面的目录），保留原文件与 references 的路径：

- `~/.agents/skills`
- `~/.codex/skills`
- `~/.pi/agent/skills`

可用 `VITRIP_LARK_SKILLS_DIR` 指定技能父目录，多个目录用系统 PATH 分隔符连接。技能目录须包含 `lark-xxx/SKILL.md` 及其引用资源。应用通过 Pi 原生技能加载器提供技能索引，模型按需使用 read 阅读说明，不把全部正文塞进每次请求。不会自动执行这些目录下其他类型的扩展。

飞书请求遵循对应技能、当前认证与用户任务。开放工具不等于授权自动发消息、发邮件或删除资源；CLI 返回高风险确认时需展示具体操作并等待确认。登录或授权不足按 CLI 的实际结果处理。

## 产品愿景与路线图（讨论稿）

记录日期：2026-09-27。以下是产品方向与待讨论需求，**尚未实现，也不是已经承诺的交付计划**；当前能力仍以本文的使用说明和当前边界为准。

ViTrip 希望从旅行规划桌面客户端，发展为贯穿「出发前准备 → 旅途中协助与记录 → 旅行后创作 → 攻略分享与再创作」的旅行产品。桌面端适合深度规划、整理素材和创作，手机 APP 适合随身翻译、接收提醒、汇率速查与现场记录。两端围绕同一份旅行资料协作。

### 底层产品逻辑

1. **行程应当转化为行动。** 知道出发日期还不够，需要把护照、采购、入境卡等准备事项变成有截止时间、完成状态和依据的待办，再在适当时间提醒。AI 提议待办与提醒时间，确定性的调度服务负责执行；不能依赖模型临时“记住”提醒。
2. **旅行记录应当在现场低成本积累。** 地点、照片、几句感想都可以成为素材；允许旅行后在手机或电脑补充，避免要求用户当场写完整日记。
3. **内容创作应当建立在真实素材上。** 日记、日志和视频复用用户记录与行程关联信息；计划、亲历记录和 AI 补写必须可区分。模型不能把没有发生的计划写成真实经历。
4. **攻略复用应当保留来源并适配个人条件。** 借鉴别人的行程后，需要按日期、预算、出行人、节奏和偏好重新安排，同时重新核实营业时间等时效信息。二创保留来源关系，不把原作者的私人资料带入副本。
5. **贡献激励必须形成可持续的成本闭环。** 用户分享有用攻略，其他人有效采用后获得可用于 AI 服务的积分。产品积分与模型输入/输出 Token 分账记录；奖励条件、兑换额度、成本上限与反作弊规则待验证，不预设发币或金融属性。
6. **规模化数据价值来自可信记录与用户授权。** 分开统计计划、用户自述到访、素材支持到访等不同证据等级。照片、机票和酒店订单只能提供部分证据，订单或照片本身不等于实际出行。公开数据使用独立授权与聚合处理；只删除姓名不足以实现匿名化，精确轨迹、时间和稀有路线也可能识别个人。

核心闭环假设是：准备更充分、现场记录更方便，会带来更多高质量旅行素材；素材降低创作门槛，攻略复用带来新用户，贡献积分激励持续分享。这些关系需要通过用户行为验证，不能直接把内容量等同于真实出行量或商业价值。

### 功能方向与体验边界

| 方向 | 用户体验 | 第一阶段范围与约束 |
| --- | --- | --- |
| 手机 APP 与跨端资料 | 手机上查看旅行、待办和记录，电脑上继续规划与编辑 | 先确定平台与同步方案；支持离线记录、失败重试、冲突处理与删除同步 |
| 随身翻译 | 出国时快速输入文字并查看译文；后续探索语音对话和拍照翻译 | 优先文本翻译；源文与译文可对照，保留语言选择；离线支持、语音与图片能力另行评估 |
| AI 准备待办与双端通知 | 出发前提醒检查证件、采购物品、填写相关资料，手机和桌面均可通知 | “提前两三天采购”是可配置示例，不是所有事项的统一期限；证件事项可能需要更早。入境要求须有来源与核实时间 |
| 汇率快捷查询 | 手机和电脑快速查币种、换算金额 | 显示数据源、报价时间与参考口径；过期缓存不能标为实时，参考汇率与实际支付汇率分开 |
| 地点打卡与旅行记录 | 到地点主动拍照、写感想，事后跨端追加照片和留言 | 首期采用主动记录，可选定位并允许手动选地点；自动到达检测另行评估权限、耗电和误判 |
| AI 日记、日志与视频 | 旅行后选择素材，一键生成可编辑草稿或视频，再分享 | 先文字与素材导出，再视频；支持生成前筛选隐私素材、标注 AI 补写、失败重试和生成成本提示 |
| 社媒分享 | 方便分享到小红书、抖音等平台 | 先支持符合目标平台使用方式的导出与系统分享；是否可直接发布取决于平台接口与授权，不能提前承诺 |
| 攻略社区与积分 | 发布、点赞、收藏、采用、二创攻略，并获得贡献奖励 | 先验证社区复用价值，再开放积分奖励；清晰定义有效采用与署名关系，防止刷量和自我套取 |
| 全球旅行可视化 | 首页展示一定时期的旅行覆盖、路线与用户故事，远期探索 3D 地球 | 先做有口径的聚合统计；明确样本覆盖范围、计划与到访差异，不能宣称代表全球全部旅行者 |

“开心、快乐”可以来自用户自愿填写的感受或明确授权的故事，不根据上传照片数量自动推断幸福程度，也不将这类感受包装成未经定义的科学指标。

### 数据与系统设计原则

以下为架构建议，具体技术方案在对应 Issue 中决策，不要求立刻改造当前桌面工程。

- **旅行是共同上下文。** 行程条目、地点、待办、记录与素材通过稳定 ID 关联。保留计划时间、实际记录时间和修改时间；旅行时区与设备时区分开保存。
- **跨端同步独立于 AI。** 手机端、桌面端通过版本化契约同步结构化记录；素材存储与元数据分离，离线队列支持幂等上传、重试、冲突处理和删除传播。同步账号、服务端存储与推送是当前本地工程之外的新能力。
- **提醒是独立业务模块。** 待办包含关联活动、截止时间、提醒规则、来源、完成状态与用户调整记录。行程改期后重新计算未来提醒；完成或取消时停止后续提醒。区分调度、推送服务受理、设备展示和用户已读状态，不把“发出”视为“用户看到”。
- **外部能力通过适配层接入。** 翻译、汇率、通知、视频生成和社媒分享各有接口、超时、重试与降级策略，避免供应商逻辑进入核心旅行数据模型。手机或云端服务使用各自安全边界，不把现有桌面主进程的密钥直接同步到其他端。
- **原始记录与生成内容分开保存。** AI 日记和视频记录素材来源、生成版本与任务状态；失败后可重试，不覆盖用户原文。公开攻略是由用户审阅的发布副本，不能直接暴露私人旅行数据库。
- **社区关系与奖励可追溯。** 攻略发布版本、引用、二创、收藏与采用是不同事件；采用数量不等于实际出行人数。积分采用可审计流水，奖励发放幂等，撤销与异常申诉有明确规则。
- **私密资料默认私有。** 证件、订单、精确定位和照片元信息按用途最小化处理。发布前预览敏感内容；参与公共统计单独选择，保留撤回与删除机制，并说明已发布聚合结果的更新方式与限制。公开聚合应抑制小样本、稀有路线和精确时间，具体阈值后续评估。

### 建议阶段与验证方式

阶段划分是讨论起点，优先级可调整；每个阶段先验证一个明确的用户价值。

| 阶段 | 建议交付 | 主要验证 |
| --- | --- | --- |
| P0：出行助手 | 手机最小可用端与同步；双端待办提醒；文本翻译；汇率查询 | 用户是否能跨端延续旅行；提醒是否及时且不打扰；待办是否按时完成；断网是否仍可记录 |
| P1：旅行记忆 | 地点记录、跨端补充、文字日记、素材导出与分享入口 | 记录是否省力；生成内容是否忠于素材；用户是否愿意编辑、保存和分享 |
| P2：攻略复用 | 攻略发布、点赞收藏、引用二创；小规模积分试验 | 有效采用率、二创质量、奖励成本与作弊比例；不以点赞数替代复用价值 |
| P3：内容与数据扩展 | 视频生成、更多分享集成、授权聚合统计与 3D 地球 | 视频质量和成本；统计可信度与隐私风险；展示是否对用户产生实际价值 |

部分工作可以提前探索，但提醒依赖稳定时间与状态模型，社区依赖可发布的攻略副本，公共数据展示依赖证据分类与授权，不能用视觉效果替代这些基础能力。

## 本机引用链接

会话菜单和每条已保存消息提供「复制本机链接」；右侧行程与笔记本也可复制链接。链接使用稳定记录 ID，重命名不会改变链接。行程和笔记本链接指向旅行共享页面，不指向某个活动或段落。

在侧栏「打开本机链接」中粘贴即可跳转；聊天及笔记 Markdown 中的 ViTrip 链接也可点击。打包版注册 `vitrip://` 协议，可由系统唤起应用；消息链接会滚动并聚焦原消息。记录已删除或不在本机时会显示失效提示，不会跳到其他记录。

这些链接仅定位本机已有数据，不会上传记录或授予他人访问权限。当前不提供公开分享页面或跨设备同步。

## 旅行项目中的 Markdown 文档

每个旅行的文档保存在 Electron userData 下 `journeys/<journeyId>/notebook/*.md`，正文是普通 UTF-8 Markdown 文件。同一旅行的会话共享文档，不同旅行隔离；新建时禁止覆盖同名文件，更新需提交读取时的内容哈希 revision，版本冲突保留编辑草稿，可另存为。编辑器保存按顺序执行，选中文档按旅行恢复。

Agent 可用 notebook 的 list/read/write 查阅、新建和更新文档。系统提示要求把成篇结果实际保存并说明文件名；未在主回复保存时，后台整理也会获得近期对话及文档目录，按主题保存，避免把 journal 知识条目误当成文档。具体哪些内容值得成篇由 Agent 判断；停止或出错前尚未执行的写入不会凭空生成文件。测试替身验证两种保存入口和真实文件，不代表真实模型一定会对所有回答生成文档。

首次读取文档目录时，已有知识条目导入 `已有旅行资料.md`，之后不自动覆盖它；原共享手册与随手笔记仍保留。随手笔记、引用、待办、画板继续使用原本的 SQLite 存储。请通过 notebook 工具或应用编辑文档，外部直接写文件不会即时推送界面刷新。
