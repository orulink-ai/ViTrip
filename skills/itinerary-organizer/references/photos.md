# 照片采集与核对

## 搜索与选取

围绕行程中的具体地点搜索，结合城市、完整名称、地址或分店名称。酒店优先查看官网相册及对应酒店的旅行平台详情页，区分外观、公共空间和具体房型。景点优先参考景点官网、旅游局资料；旅行网站和小红书原帖可补充游客视角。

搜索结果缩略图用于发现来源，不能单凭缩略图确认地点。打开原页面，核对图片说明及上下文。小红书图片关联原帖及作者；多地点笔记须核对每张图片，不把整篇标题自动套用到全部图片。页面无法访问或需要登录时保留实际限制，不声称已读到原帖。

## 来源访问失败时

同一站点持续连接失败时换独立来源，不靠反复改相册路径重试。工具已报告不可用时，不重复提交同一目标；不要为找一处照片耗尽整轮时间而遗漏其他地点。

及时用 journal 保存已核对的地点页面和候选资料，再处理下一处。只确认了地点页面、没有读到具体图片时，明确记录“地点页面已找到，照片待采集”，状态为 pending，不能算作已取得照片。所有来源均失败时也保存该地点的照片待办与已知限制，不编造图片或把尝试访问的网址写成已核实来源；避免整轮结束只留下口头进度。不要把完整工具日志写入共享资料。

## 证据记录

在当前工具支持的范围内，为照片候选保留：

- 关联的酒店或景点，以及可区分的分店、地址、房型。
- 来源页面 URL、页面标题、平台或发布者；实际观察到的图片 URL 或采集工具返回的资源标识。不能推测或拼造图片地址。
- 支持对应关系的原文说明或上下文，以及采集时间；发布时间、拍摄时间仅在页面提供时记录，不能互相替代。
- 图像类别，如酒店官方宣传图、平台展示图、作者声称的游客实拍、效果图。注明页面依据；不能仅凭照片风格认定是实拍。
- 已核对哪些信息、仍不能确认哪些信息。官网展示图也不自动证明当前房间状态、景观或设施情况。

这些是整理要求，不是可直接传给 plan 的新增字段。使用当前 schema；图片字段尚不可用时，把候选说明和来源链接存入 journal 的 reference 或 pending 条目，沿用稳定 id 避免重复。

## 多模态辅助

先确认本轮工具是否返回实际图片，以及所用模型和接入接口是否接受图片。文字、URL 或图片 alt 文本不等于模型已看到图像。模型可以辅助区分建筑、房型、标识和图片内容；地点对应关系仍需页面证据，不能由视觉相似度单独证明。

找不到可靠照片时保留空缺或待核对候选；不使用生成图替代实拍，不套用同品牌其他酒店或相似景点照片。

## 呈现与复核

行程和地图共用同一地点的照片资料；显示图片说明与来源入口，支持查看大图。来源标注应区分官方展示和游客发布。保留原图内容，不去除水印；不能读取原图时不要将页面截图冒称为原始照片。

采集成功、确认对应关系、保存候选、界面显示是不同结果。分别根据工具结果和实际页面反馈报告，不因 Skill 中有展示要求就声称相册已经实现。
